= Changelog

== Unreleased

* Dark mode: preview screenshots on extension detail pages (gallery image and thumbnails), extension cards and the Featured slot no longer sit on a white backing; it's charcoal (#111111) in dark mode and stays white in light mode.
* Layers, bundles and previews. Every extension now has a layer (Engine, Chassis, Body kit, Paint & trim, Bolt-on, the antora-ui-chassis names) declared with `"antoraRegistry": {"layers": [...]}` in package.json or `layers:` in `antora-registry.md`, or guessed and marked "inferred". Bundles are detected from a declared `bundle`/`kind: bundle`/`purpose: compose-pack`, a bundle keyword, or 3+ dependencies on indexed extensions, and get a Bundle badge with their contents. Previews come from `antoraRegistry.previews`, else README images, plus admin-added URLs; cards show a thumbnail and detail pages a gallery (antora-search-chat ships with demo screenshots). Search groups results into per-layer boxes (a side column on desktop, an expandable list on mobile; clicking a name scrolls to and highlights the result), adds a Layers filter with an Unclassified group, and a Bundles kind (`ui-recipe` is now "UI recipes"). The home page has an admin-configurable Featured slot, defaulting to facto-stack, now listed as a curated repo. `/admin` gains a Catalog metadata card for layer and bundle overrides, preview URLs and the featured ids. New tables `catalog_override` and `catalog_preview`; the deploy workflow now applies the schema before building. Documented in the new Registry metadata docs page.
* Docs: new design spec page "Antora Extension Registry: Accounts, Stacks, Quality & Trust" (spec v0.2+, `docs/modules/ROOT/pages/design/trust-and-quality-spec.adoc`, under Design in the docs nav), recorded from the working-draft Page. It covers accounts, collections and stacks, the stack install CLI, curation and lifecycle states, maturity tiers, indexing, outreach and claims, security scanning, appeals and bans, the AI reviewer and AI provider settings, trusted publishers and trust requests, ratings, flags, redemption, abuse controls, admins and verdicts, the data model, flows, email, rollout and open questions. Design only; nothing in it is implemented by this change.
* Admin review queue: Approve and Reject buttons (admin-only server actions, checked on the server). Reject takes an optional reason and keeps the record (status `rejected`, note, reviewer, date) and drops the repository's catalog entries; rejected repositories are never auto-imported again. Approve publishes the theme or extension (re-checked from GitHub). Each row shows the outcome.
* Discovery runs once a day (09:00 UTC) instead of every 6 hours. Admin "Run discovery" now checks up to 8 new repositories per run and imports the ones that pass, listing each result and its failed criteria.
* `/add`: signed-in users can check a repository now ("Check a repository now"). It's validated against the registry criteria (public, one primary topic, README, license; themes: declared appearance, preview.png, demo, valid `antora-theme.json`, existing `baseTheme`; extensions: at least one catalog entry) and listed right away if it passes, otherwise every failed criterion is listed. 5 checks per user per hour, each logged in `repo_check`.
* Theme appearance: themes declare light, dark, both or other with the topics `antora-light-theme`, `antora-dark-theme` (both for light + dark) or `antora-other-theme`, or with `appearance` in an `antora-theme.json` manifest (the manifest wins; disagreeing declarations fail the check). Theme filters are Light, Dark, Light + dark and Other, each an exact class. A pure color re-theme can name its `baseTheme` in the manifest and the card shows "Color re-theme of …"; forks aren't treated as re-themes. The old appearance inference (wildcard and category topics, dark-mode overlay detection) is removed; extensions keep a "Dark mode add-ons" filter.
* Trusted publishers: new `trusted_publisher` table (GitHub user/org, GitLab user/group), seeded with the `antora-supplemental` GitHub org. Submissions are approved without review when the repository owner is trusted or the submitter's linked GitHub/GitLab login, or public GitHub org membership, matches. Expedited checks and discovery record the trust reason. `/admin` adds and removes entries and lists recent automatic approvals with the reason.
* Reports: signed-in users can report an extension (detail page) or theme (card) as low quality, broken, malicious/security, spam, license or other, with an optional message up to 2000 characters. One open report per user per item and 10 reports per user per day. Reports are stored in `report` and listed on `/admin` with Resolve and Dismiss. Each new report is emailed as plain text through the Resend API to `REPORT_EMAIL_TO` (default support@antora-supplemental.org) when `RESEND_API_KEY` and `REPORT_EMAIL_FROM` are set; otherwise it's logged and only stored.
* "New" badge on extension and theme cards, the extension detail page and search suggestions for items first listed in the last 30 days (`NEW_WINDOW_DAYS`). The first-listed date lives in the new `first_listed` table, is written once and never changes on re-import or update; existing items are backfilled from their earliest record (repository or theme creation date). `/search` gets a New filter (`&new=1`, newest first); the extension and theme galleries get "New only" and "Newest first". Badge colors are AA in both schemes (light #9A3412 on #FFF4ED, 6.9:1; dark #FFC9A8 on #431407, 10.6:1).
* `/add`: the signed-out notice no longer promises to bring you back to the form; "every few hours" is now "once a day".
* Dark mode: small grey meta text on cards (versions, ids, authors, dates) goes from #737373 (3.59:1 on charcoal) to #a3a3a3 (about 7:1) for AA.
* The light/dark toggle button switches its icon and colors instantly (its own color transition is removed); page color transitions are unchanged.
* Home search always searches everything (the All/Extensions/Themes chips are gone) and now suggests as you type: up to 8 extension and theme names (prefix, word and fuzzy match, each labeled with its kind) that open the item directly, while Enter goes to `/search?q=`. Focusing the empty box lists the categories (Antora extensions, UI modules, Bundles, Themes). Keyboard (Up/Down, Enter, Esc, Tab), ARIA combobox, closes on blur. `/search` gains All / Extensions / Themes filters plus extension-kind filters, kept in the URL (`&type=themes`, `&kind=ui-module`).
* Light-mode contrast pass (axe color-contrast, every route, desktop and mobile): sign-in provider labels were white on white (now #111111); orange badges and the Copy button were #C2410C on a primary/20 tint at 4.03:1 (tint now #FFF7ED, 4.87:1; hover #FFEDD5, 4.52:1); amber and emerald badges were 1.31:1 and 1.36:1 (now #92400E and #065F46); the sign-in notice on `/add` and the submit pages sat on an unmapped grey (#404040 text 4.2:1, link 2.1:1; now white); theme star counts were 1.5:1 (now #A16207); green and red status text gets darker light-mode steps. The sign-in subtitle is back to "Choose a provider to continue".
* New `/add` guide, "Add to the registry": shared steps (topic, README, license, sign in, submit, review), a Themes section (preview.png, live demo, screenshot workflow, starting points, moved from the theme submit page), an Extensions section (topic, `antora-dark-mode` tagging, optional manifest with a docs link) and what happens after you submit. Linked from the home page, both browse pages and the nav, where "Submit" replaces "Submit Theme". `/submit` now goes to `/add`.
* New admin-only `/admin` page (`ADMIN_GITHUB_LOGINS`, comma-separated GitHub logins): review queue, catalog sync status, topic-discovered repos, load errors, manifest paths, API endpoints and topic schema, and a "Run discovery" button (`POST /api/admin/discover`, read-only preview). The account page shows an Admin link to admins.
* New `/extensions/submit` form (posts to `POST /api/extensions/submit`) and an "Add your extension" button on `/extensions`.
* Home search *All* now lands on a combined `/search?q=` page with extension and theme results (was `/extensions?q=`).
* Copy pass: plainer home cards, extensions and themes intros, loading and error text, theme form states ("Repository found", "Submitted for review"), sign-in subtitle, account linking text, footer tagline "Antora Registry — community extensions and themes", and a "Browse themes" link on the 404 page. Repository topics, discovery counts, the Catalog API block, catalog load errors and manifest paths move from public pages to `/admin`; the extension detail page no longer shows the manifest path or internal ID.
* Extensions filters: type is All / Single extensions / Bundles; color mode offers "Dark-only themes", "Dark mode add-ons" and "Other color schemes" ("Dual appearance" removed, "Dark" now means dark-only). Dark mode add-ons are no longer hidden by default, and the count reads "N extensions".

* Sign-in honors a same-site `?redirect=` path, so signing in from a submit form returns you to it. Signed-out visitors to a submit form land on `/add` with a sign-in notice.
* Theme toggle tooltip now matches its accessible label.

The Extensions page title and intro, the home CTA, the home Extensions card, the Extensions search placeholder (was "Search modules and recipes..."), the `antora-extension` topic description, and the site description and og/twitter meta now cover build-time pipeline extensions, CI checkers and validators, generators, utilities, and UI-side modules. UI modules remain one category within extensions.
* Removed the purple-glass trims: the `--trim*` and `--glass-*` tokens, the Tailwind `trim` color, the violet rims, rules, nav underline, mode-icon borders and selection color are gone, back to the `design-orange-v1` look. The mobile header toggle and the extensions wording are kept.

The solid-ui `primary`/`accent`/`ring` tokens and the Tailwind `primary` scale map to the orange; the `--brand-grad-*` variables are gone. Light-mode orange text uses #C2410C for AA contrast. The search glow is a subtle solid-orange blur.

Previously no route matched, so SolidStart served an empty app shell with HTTP 200 (an earlier attempt never wrote the file because PowerShell treated `[...404]` as a wildcard).
