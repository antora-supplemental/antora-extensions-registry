= Changelog

== Unreleased

* Display titles: cards, search and package headings use `antoraRegistry.title`, then `package.json` `displayName`, then the README's first heading, then a humanized package name (scope stripped, words title-cased, acronyms such as UI, CSS and TOC kept). The raw package name stays visible as a muted monospace line on the package page and in title tooltips.
* Unique display titles (soft): titles are unique across the registry, compared ignoring case and punctuation; fork-grouped entries are excluded and identity stays host/owner/repo/package. The entry first indexed with a title holds it (first-seen times in a new `title_claim` table, created by the sync). Later entries are still listed but show the owner (plus GitHub/GitLab when hosts differ) after the title on cards and in search, and their package page shows a "title already in use" notice asking the author to set a unique `antoraRegistry.title`; the sync log lists each conflict. When the holder renames or leaves, the title passes to the next earliest entry at the next sync. Indexing is never blocked.
* npm (optional extra info, not identity): the sync records an npm name only when the npm package's repository is the same owner/repo, and the package page adds an "also on npm" link.
* Compatibility: declared `requires`/`worksWith` and satisfied `provides`/`uses` contracts now take precedence over the same-layer "alternatives" inference, and a contract-guaranteed link outranks a plain declared one. Only exclusive layers (engine, body kit, paint) produce alternatives, and only when nothing relates the two packages; composable layers (chassis, extensions) never do. Declared names also resolve by a monorepo package's `package.json` name, so `@antora-supplemental/color-scheme` finds the chassis color-scheme entry.
* Monorepo packages (for example antora-ui-chassis) now get per-package releases, Antora compatibility, relations and color schemes. Each package reads its own `package.json` and maps `<package>-v<semver>` tags (such as `color-scheme-v0.5.3`) to its own install specs. The singular `layer` field in a registry index is now honored, so layers show as declared instead of inferred.
* Package detail pages list "More from this repo" siblings and show repository-level details (stars, repository, package directory). Browse cards for packages from a multi-package repo show a "part of <repo>" badge.
* Retired the curated compatibility seeds for color-scheme, light-dark-mode and default-paint, which now declare their own `antoraRegistry` blocks.
* Default UI with light/dark mode (`gitlab.com/AMDphreak/antora-ui-default`, branch `feat/root-theme-transition`) is indexed and takes the home page's Default UI slot in Featured Themes, with its light and dark scheme swatches. The stock Default UI's page shows a generic "Also available with light/dark mode" link (curated `variantOf` on theme entries); the fork's schemes stay on the fork. GitLab-hosted packages now get the same repo-level extras as GitHub ones: `antoraRegistry.antora`, relations and contracts, and color schemes. Curated theme entries can set a forge `host` and their own preview image.
* Header Themes link: the light-mode rainbow is full strength (no darkening toward the text color); dark mode is unchanged.
* Preview screenshots are captured with scrollbars hidden and no scrollbar gutter; the Skittles preview was regenerated.

* Package-to-package compatibility: `antoraRegistry` `requires`/`worksWith`/`conflictsWith` and `provides`/`uses` contracts, computed at sync into the snapshot and a new `catalog_compat` table. Detail pages show *Works with* (declared, curated, guaranteed, likely, with reasoning tooltips), *Conflicts with*, alternatives in the same layer, and an Antora-version overlap warning. Curated seeds cover the chassis packages and the stock Default UI.

* Scheme swatches and light/dark circles now always render in label order (light, both, dark, other, then declared order) via one shared sort.
* Antora version compatibility per release. The sync reads each repository's releases and tags and resolves the Antora line of every release: `+antora.N` (or `+antora-solid`) build metadata on the tag or an alias tag, then `engines.antora` at that tag, then core `@antora/*` peer dependencies, then the repository's `antoraRegistry.antora`; otherwise "not declared". Rolling tags (`v4`, `v4.2`) follow the newest release they cover. Package pages show a "Releases by Antora version" table with the latest release per line, install specs and bundle download links; cards show "Antora N" badges and the extensions page filters by Antora version. New `catalog_release` table (applied by `drizzle-kit push`). Documented on Registry metadata.
* Color schemes: a paint that sets `antoraRegistry.colorSchemes` gets one swatch chip per scheme from its `@color-schemes` comment (canvas, accent, link and text colors), on cards and, with labels, on the package page.
* Skittles (`antora-supplemental/skittles-theme`) is listed: in the theme gallery and as a package with its 11 color schemes, previews and Antora 3 compatibility.
* Theme detail pages at `/themes/<owner>/<repo>` (forwarding to the package page when the repository is also a catalog package). Theme names on cards are real links to them and the preview opens them too, on the home page Featured Themes, `/themes` and search; middle-click and open in new tab work. The card thumbnail link is one shared component (`CardPreviewLink`) for theme, extension and featured cards.
* Thumbnail overlay buttons (Live Demo, repository) no longer take clicks while hidden: they get `visibility: hidden` and `pointer-events: none` until hover (fine pointers only) or focus, and become clickable 60 ms after the reveal starts. On touch the tap opens the item instead of firing a hidden button.
* The Report button is only on item detail pages now, no longer on cards.
* Home hero: the Extensions and Theme Gallery buttons share the gray secondary style, so search is the one primary action. Secondary buttons get a visible hover shade in light mode.
* Light mode: the header "Themes" rainbow uses saturated hues at 90% opacity (10% darkening toward the text color instead of 60%). Dark mode unchanged.

* GitLab support: topic discovery on gitlab.com (`antora-extension` and related topics; optional `GITLAB_TOKEN` for rate limits), the same enrichment as GitHub (package.json, `antora-registry.md`, README, previews, layers, default branch), forks grouped with their upstream across hosts, a GitLab icon and link wherever a repository is shown, and install snippets that use the right git URL. `gitlab.com/antora/antora-lunr-extension` is a curated seed.
* Owner line: package name first at title size, then a muted line with a 16px round avatar and the owner name (no "by"; "@" only for an npm scope) linking to the new `/owners/<host>/<login>` page, plus a forge icon linking to the profile. A prop flips the order. The accessible name stays `owner/repo` with a single heading. Used on cards, the detail heading, fork rows and GitLab entries.
* Owners: the sync stores owner metadata (type, display name, profile, package count) in a new `owner` table and caches each avatar at 64px under the preview-cache rules. `/owners/<host>/<login>` lists that owner's extensions with a count.
* Layers: one shared classifier (`lib/layers.ts`) for cards, detail pages and the sync. Declared or admin layers win, then topics (`antora-theme`/`antora-paint` → Paint & trim, `layout` → Body kit, and others); "paint" is no longer guessed from words like "theme" in descriptions. Theme swatches show only for paint/theme packages. Fixes article-zones showing a "Dark theme" swatch.
* `/previews/<hash>` fixed: blob bytes are read correctly from every libsql client shape, and errors return 503 with a header-safe `X-Preview-Error` tag instead of an unhandled 500.
* Faster cold loads: the sync writes a denormalized browse snapshot (`browse_snapshot` in `catalog_meta`), so extension pages read one row instead of several tables in sequence, and the catalog overlay reads are batched into one round trip. Anonymous browse pages are cached at the Netlify CDN (`s-maxage=300, stale-while-revalidate=86400`, tag `registry-browse`, varied on the session cookie; signed-in pages are never shared) and purged after each sync when `NETLIFY_AUTH_TOKEN` and `NETLIFY_SITE_ID` are set.
* Home search dropdown: removed the redundant "All extensions" option, since every listed extension is Antora-specific.

* Preview cache: the daily sync downloads each preview image the first time it answers 200 with an `image/*` type (up to 5 MB), stores it by SHA-256 in the registry database (new `preview_blob` and `preview_cache` tables, created by the sync) and serves it from `/previews/<hash>` with an immutable cache header. Pages use the cached copy, so a slow or rate-limited raw.githubusercontent.com no longer matters. A URL whose first fetch fails is never cached or shown. When a cached URL later 404s, stops returning an image, or is no longer referenced by the README, the cached copy stays and is marked stale internally. A different valid image refreshes the cache. Cached images belong to a package and are purged when it leaves the catalog. This replaces the sync's drop-dead-previews step. If a cached copy ever fails to load in the browser, the image falls back once to its original URL; the route answers 404 for an unknown hash and 503 when the database is unreachable.
* Forks: forks of the same upstream repository (from GitHub `fork`, `parent` and `source`) are grouped. Search shows one card per group with a `+N forks` badge, and the package page shows "N versions available" listing the upstream and each fork with owner, last commit date, stars, npm name when it differs, and ahead/behind from the GitHub compare API. A fork is listed only when it has its own `antora-extension` topic (curated repositories always are). Topic discovery now includes forks (`fork:true`) and reads up to 300 results instead of 30.
* Seed list: added `antora-supplemental/antora-diagram-engines` (diagram-lightbox and mermaid-client via its `registry-index.json`).
* Extension detail pages: the Install section opens with one or two sentences saying what the snippet is and where it goes (extension, compose pack, UI module or UI recipe; based on type, bundle and layer) and ends with a "Full installation guide" link to the new docs page "Installing from the registry", which covers the playbook location, install commands, where each snippet goes in `antora-playbook.yml` (with an annotated playbook illustration in light and dark), themes, and how to check that it worked.
* Preview screenshots open in an in-page lightbox instead of a new tab: previous/next buttons that wrap around, left/right arrow keys, Esc or a backdrop click to close, focus kept inside while open and returned to the image afterwards, an "n / total" counter with the caption, and touch swipe. Navigation is hidden when there is only one image.
* "Used by" on extension pages now reads in the right direction: each tag says "requires this" or "recommends this" after the dependent's name, instead of a bare "requires" that looked like the page's own dependency. Two packages that depend on each other get a "mutual" tag.
* Bundles in the dependency view: a bundle's members now appear in its Dependency tree as `bundles` edges, and each member's "Used by" lists the bundle with a "bundled in" tag (name first, then the relationship). Bundle contents match members to catalog entries by npm name, then by `@<repo owner>/<module id or repo name>`, so entries whose catalog name is a display name (for example Chassis compose) are linked again. Members that are not in the registry link out to their repository (from the package.json dependency spec, now stored as `dependencySpecs` by the catalog sync) or npm, with a "not in registry" note.
* The header "Themes" link (desktop and mobile menu) has a 30deg rainbow on its letters only, at 40% opacity over the normal text color: an aria-hidden copy of the label with the gradient clipped to the glyphs (`background-clip: text`), so nothing paints behind or around the text. The one intended exception to the no-gradients rule.
* README preview images no longer break: URLs use the repository's default branch (or `HEAD`) instead of a hard-coded `main`, AsciiDoc `image::` targets resolve against `:imagesdir:`, Markdown paths resolve against the README's folder, and any image that does not answer 200 with an `image/*` type is dropped. When none survive, the gallery and thumbnail are hidden. The daily catalog sync re-checks every stored preview URL and drops dead ones; `pnpm test` covers the extraction rules and `pnpm audit:previews` audits the whole catalog.
* Docs build: added the missing `@antora/lunr-extension` dev dependency, and the docs hub link on the docs home page is now a URL instead of a broken `home:ROOT` xref.

* Extension detail pages have a Full description section below the summary. It shows `antoraRegistry.longDescription` (package.json or `antora-registry.md`) when a package sets one, otherwise the README intro: the prose before the first second-level heading, without badges or images, at most three paragraphs. It never shows the whole README and ends with a "Read the full README" link. Stored in the catalog entry payload, so no schema change. Documented on the Registry metadata page.

* Dark mode: preview screenshots on extension detail pages (gallery image and thumbnails), extension cards and the Featured slot no longer sit on a white backing; it's charcoal (#111111) in dark mode and stays white in light mode.
* Layers, bundles and previews. Every extension now has a layer (Engine, Chassis, Body kit, Paint & trim, Bolt-on, the antora-ui-chassis names) declared with `"antoraRegistry": {"layers": [...]}` in package.json or `layers:` in `antora-registry.md`, or guessed and marked "inferred". Bundles are detected from a declared `bundle`/`kind: bundle`/`purpose: compose-pack`, a bundle keyword, or 3+ dependencies on indexed extensions, and get a Bundle badge with their contents. Previews come from `antoraRegistry.previews`, else README images, plus admin-added URLs; cards show a thumbnail and detail pages a gallery (antora-search-chat ships with demo screenshots). Search groups results into per-layer boxes (a side column on desktop, an expandable list on mobile; clicking a name scrolls to and highlights the result), adds a Layers filter with an Unclassified group, and a Bundles kind (`ui-recipe` is now "UI recipes"). The home page has an admin-configurable Featured slot, defaulting to facto-stack, now listed as a curated repo. `/admin` gains a Catalog metadata card for layer and bundle overrides, preview URLs and the featured ids. New tables `catalog_override` and `catalog_preview`; the deploy workflow now applies the schema before building. Documented in the new Registry metadata docs page.
* Docs: new design spec page "Antora Extension Registry: Accounts, Stacks, Quality & Trust" (spec v0.2+, `docs/modules/ROOT/pages/design/trust-and-quality-spec.adoc`, under Design in the docs nav), recorded from the working-draft Page. It covers accounts, collections and stacks, the stack install CLI, curation and lifecycle states, maturity tiers, indexing, outreach and claims, security scanning, appeals and bans, the AI reviewer and AI provider settings, trusted publishers and trust requests, ratings, flags, redemption, abuse controls, admins and verdicts, the data model, flows, email, rollout and open questions. Design only; nothing in it is implemented by this change.
* Admin review queue: Approve and Reject buttons (admin-only server actions, checked on the server). Reject takes an optional reason and keeps the record (status `rejected`, note, reviewer, date) and drops the repository's catalog entries; rejected repositories are never auto-imported again. Approve publishes the theme or extension (re-checked from GitHub). Each row shows the outcome.
* Discovery runs once a day (09:00 UTC) instead of every 6 hours. Admin "Run discovery" now checks up to 8 new repositories per run and imports the ones that pass, listing each result and its failed criteria.
* `/add`: signed-in users can check a repository now ("Check a repository now"). It's validated against the registry criteria (public, one primary topic, README, license; themes: declared appearance, preview.png, demo, valid `antora-theme.json`, existing `baseTheme`; extensions: at least one catalog entry) and listed right away if it passes, otherwise every failed criterion is listed. 5 checks per user per hour, each logged in `repo_check`.
* Theme appearance: themes declare light, dark, both or other with the topics `antora-light-theme`, `antora-dark-theme` (both for light + dark) or `antora-other-theme`, or with `appearance` in an `antora-theme.json` manifest (the manifest wins; disagreeing declarations fail the check). Theme filters are Light, Dark, Light + dark and Other, each an exact class. A pure color re-theme can name its `baseTheme` in the manifest and the card shows "Color re-theme of …"; forks aren't treated as re-themes. The old appearance inference (wildcard and category topics, dark-mode overlay detection) is removed; extensions keep a "Dark mode add-ons" filter.
* Trusted publishers: new `trusted_publisher` table (GitHub user/org, GitLab user/group), seeded with the `antora-supplemental` GitHub org. Submissions are approved without review when the repository owner is trusted or the submitter's linked GitHub/GitLab login, or public GitHub org membership, matches. Expedited checks and discovery record the trust reason. `/admin` adds and removes entries and lists recent automatic approvals with the reason.
* Reports: signed-in users can report an extension (detail page) or theme (card) as low quality, broken, malicious/security, spam, license or other, with an optional message up to 2000 characters. One open report per user per item and 10 reports per user per day. Reports are stored in `report` and listed on `/admin` with Resolve and Dismiss. Each new report is emailed as plain text through the Resend API to `REPORT_EMAIL_TO` (default support@antora-supplemental.org) when `RESEND_API_KEY` and `REPORT_EMAIL_FROM` are set; otherwise it's logged and only stored.
