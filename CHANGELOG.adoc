= Changelog

== Unreleased

* Mobile header shows the light/dark toggle next to the menu button; the duplicate toggle inside the menu sheet is removed.
* Wording: extensions are no longer described as UI-only. The Extensions page title and intro, the home CTA, the home Extensions card, the Extensions search placeholder (was "Search modules and recipes..."), the `antora-extension` topic description, and the site description and og/twitter meta now cover build-time pipeline extensions, CI checkers and validators, generators, utilities, and UI-side modules. UI modules remain one category within extensions.
* Removed the purple-glass trims: the `--trim*` and `--glass-*` tokens, the Tailwind `trim` color, the violet rims, rules, nav underline, mode-icon borders and selection color are gone, back to the `design-orange-v1` look. The mobile header toggle and the extensions wording are kept.
* Hero: eyebrow now reads "Unofficial Registry" (asterisk link removed); the heading is a large plain "Antora" followed by "Extensions & Themes". The ANTORA knockout and the `KnockoutText` component are removed. The footer disclaimer drops its leading asterisk.
* Palette: replaced the sky/indigo gradient branding with solid colors only: neutral charcoal greys (#111111 base), white text, and one signal-orange accent, `--brand` #FF5F00 with `--brand-foreground` #111111, for buttons, active states, the logo tile, focus rings and links. The solid-ui `primary`/`accent`/`ring` tokens and the Tailwind `primary` scale map to the orange; the `--brand-grad-*` variables are gone. Light-mode orange text uses #C2410C for AA contrast. The search glow is a subtle solid-orange blur.
* Unknown routes (including the removed `/registry`) now render a *Page not found* page with HTTP 404 via a `[...404].tsx` catch-all and `HttpStatusCode`. Previously no route matched, so SolidStart served an empty app shell with HTTP 200 (an earlier attempt never wrote the file because PowerShell treated `[...404]` as a wildcard).
* Native search clear buttons (`::-webkit-search-cancel-button`, `::-ms-clear`) are hidden so long queries fade cleanly at the input edge.
* Footer tagline: "extensions and themes for the Antora community" (was "extensions, themes, and packages").

* New extension detail page at `/extensions/<owner>/<repo>/<id>` with key info, install snippet, a requires/recommends dependency tree (cycle- and depth-guarded, same-repo ids preferred) and a "Used by" list; extension cards link to it.
* Homepage search *All* now lands on `/extensions?q=...`; the extensions page reads `?q=` to pre-filter.
* Removed the `/registry` prototype page (no redirect), its nav links, the homepage *Package search* button and *Packages* card, and the dead components (`SearchTree`, `ExtensionPanel`, `DependencyButton`, `InstallMethods`, `lib/registry/*`) and CSS (`.glass`, `.premium-gradient`, `.side-panel`, `.dependency-tree-node`, custom `.animate-in`).
* Site-wide Light/Dark toggle (sun/moon, desktop header and mobile menu). Follows `prefers-color-scheme` on load; a manual choice persists in `localStorage` until the OS scheme changes, which switches live and clears it. An inline head script applies the scheme before paint.
* Wording: the site is described as an unofficial, community-run catalog not affiliated with or endorsed by the Antora project (meta description). The hero shows a short *Unofficial** marker whose asterisk links to the footer note `#disclaimer`: "* Not affiliated with or endorsed by the Antora project."
* Homepage hero: removed the "One catalog for the Antora ecosystem..." paragraph; that summary now lives only in the `description`, `og:description` and `twitter:description` meta tags.
* Homepage hero heading is now "Extensions & themes for ANTORA" (dropped "Discover"). *ANTORA* sits on its own line as a knockout cut out of a near-square block filled with a diagonal brand gradient (`--brand-grad-from/via/to` in `app.css`), via the shared `KnockoutText` component; accessible text stays "Antora".
* Homepage search box gets the bloom from the old `/registry` search (blurred primary/indigo gradient halo, brighter on focus, tuned per scheme); placeholder no longer mentions packages. Long queries fade out before the input meets the *Search* button (`.search-fade-end`).

* Search inputs with an icon (`/registry`, themes gallery): padding reserves the icon area and long queries fade out (CSS `mask-image`) before running under the icon; the box chrome moved to a wrapper with `focus-within` ring.
* `/registry` hero: *EXTENSIONS* is now a true knockout (letters cut out of a gradient pill via an SVG mask, real text kept for screen readers). It was invisible because `.premium-gradient` used the `background` shorthand, which reset `bg-clip-text` to `border-box` on `text-transparent` text; the class now sets `background-image` only.
* Fix: client-side navigation to `/` from any page threw "Uncaught Client Exception" (blank home). The home route imported the server-only `loadGalleryThemes` (Drizzle + `~/env/server`) directly, so env validation ran in the browser on soft-nav; it now uses the `'use server'` `loadThemes` query.
* Themes gallery: default appearance filter is now *All* (was *Light + dark themes*, which hid every theme not tagged with both modes); *All* is selectable again.
* Header (mobile): wordmark hidden below `sm` (logo stays the home link); Extensions/Themes/Registry/auth links move into a solid-ui Sheet hamburger menu below `md` (labelled trigger, focus trap + Escape, closes on navigation). Desktop unchanged.
* Home hero: eyebrow heading reads *Antora Extension Registry* instead of the bare domain.
* Auth UI: sign-in provider brand marks (GitHub mark in `currentColor`, GitLab tanuki in brand orange; Simple Icons paths inlined in `~/components/icons/ProviderIcon`, generic key fallback) on `/auth/signin` buttons, `/auth/account` linked sign-ins and Link buttons, and the merge provider picker.
* Sign in with GitLab via OpenID Connect (better-auth genericOAuth, discovery + PKCE, scopes `openid profile email`; callback `/api/auth/oauth2/callback/gitlab`; optional GITLAB_ISSUER for self-managed GitLab) when GITLAB_ID/GITLAB_SECRET are set; GitLab auto-links only when `email_verified` is true; sign-in and account pages only show configured providers. Account page gains *Linked sign-ins* (link/unlink, last one protected; GitHub/GitLab auto-link only on matching verified email) and *Merge another account* (fresh sign-in on both accounts, transactional merge with audit row in account_merge_audit).
* UI: adopt solid-ui (Kobalte + cva + tailwind-merge v2, Tailwind 3.4). Theme tokens mapped to the existing slate/sky palette; cards, badges/tags, buttons and search inputs now use `~/components/ui`.
* Overscroll: `html`/`body` background now use `--chrome-bg` (slate-900 `#0f172a`, the header/footer color) in both schemes, so trackpad rubber-banding no longer flashes white.
* Theme/extension cards: dark/light mode tags render as circular color-composite icons (contrasting border, `Dark theme` / `Light theme` labels) on their own row instead of tag pills.
* Database: Turso-backed catalog. New `catalog_entry` / `catalog_meta` tables; `pnpm catalog:sync` (scheduled `catalog-sync.yml` every 6h, plus dispatch) fetches repos/modules/versions with the built-in `GITHUB_TOKEN` and upserts them. The site reads the catalog from the DB (`dataSource: database` in `/api/extensions/catalog`), falling back to the build snapshot. `REGISTRY_CATALOG_ONLY=false`; `BETTER_AUTH_URL` is now `https://registry.antora-supplemental.org`; featured themes keep the curated order (Default UI first).
* Netlify SSR staging: cross-platform `server.zip` rebuild (Windows `tar -a`), normalize `manifest.json` paths, copy required packages (`pathe`) into the Lambda bundle; fail staging if `server.zip` is missing.
* DNS: Cloudflare CNAME `registry.antora-supplemental.org` → `antora-extensions-registry.netlify.app` (2026-10-21).
* Docs: hub xref now targets component `home` (was `docs`).
* Catalog: index `antora-ui-chassis` playbook extensions (`soft-nav-context`, `chassis-compose`) via `registry-index.json`.
* SSR bootstrap: catalog-only mode on Netlify when Better Auth / Turso env is missing (avoids hard 502; full auth/search still needs Netlify secrets).
* Netlify follow-up: Lambda runtime detection, in-memory LibSQL for catalog-only, `REGISTRY_CATALOG_ONLY=true` in `netlify.toml` until Turso + Better Auth are set.
* Netlify SSR: declare `pathe` dependency so the server function bundle resolves Vinxi imports; set production runtime `REGISTRY_CATALOG_ONLY` in `netlify.toml`.
* Netlify deploy: stage `.netlify` into `dist/` after build; set `functions-dir` in GitHub Actions so SSR `server.zip` deploys with static assets.
* Netlify SSR: materialize pnpm-linked deps (e.g. `pathe`) before re-zipping the server function for Lambda.
* CI: fail Netlify deploy when `NETLIFY_AUTH_TOKEN` / `NETLIFY_SITE_ID` secrets are missing (avoid green builds that skip upload).
* Document canonical hostname `registry.antora-supplemental.org` vs stale `registry.antora-extensions.org` (`DOMAIN.adoc`).
