= Email and password sign-in
:page-date: 2026-10-26

== What changed

* better-auth `emailAndPassword` is on next to the OAuth providers. Sign in, Create account and (when email is enabled) Forgot password live on `/auth/signin`; `/auth/reset-password` sets a new password from an emailed link.
* Passwords are hashed with argon2id (`hash-wasm`, WebAssembly, so no native addon in Netlify Functions): 19 MiB, 2 iterations, 1 lane. Length-only policy: 12 to 256 characters, no composition rules. Breached passwords are refused through the Have I Been Pwned range API (k-anonymity; only a 5-character hash prefix leaves the server).
* Emails are lowercased before every lookup. Sign-up never auto-signs-in, so a sign-up for an existing email gets the same response as a new one; credential failures all read "Email or password is incorrect."
* Rate limits: per IP through better-auth's limiter stored in Turso (`rateLimit` table; sign-in 10/min, sign-up 10/h, reset and magic link 5/h), and per account in `auth_attempt` (sign-in locks for 15 minutes after 5 failures in 15 minutes; sign-up, reset and magic link 3/h per email). Netlify's `x-nf-client-connection-ip` is the client IP.
* Linking: a password is added to an existing (for example GitHub) account only after the inbox is proven, through a "set a password" link that is sent when someone signs up with that email. That path needs email verification on. If an OAuth provider links to a user whose email was never verified, any password on it is removed and its sessions end (pre-hijack guard).
* Auth email (magic link, verification, reset) is sent with the Resend HTTP API using `RESEND_API_KEY` and `EMAIL_FROM`. This replaces the magic-link stub that threw in production.
* Migration: `drizzle/0001_password_auth.sql` (idempotent), also applied at runtime on the first auth request.

== Environment

[cols="1,3"]
|===
|Variable |Purpose

|`RESEND_API_KEY`
|Resend key (already used for reports). Required for any auth email.

|`EMAIL_FROM`
|Sender for auth email, on a domain verified in Resend, e.g. `Antora Registry <auth@antora-supplemental.org>`.

|`AUTH_EMAIL_VERIFICATION`
|Feature flag. `true` requires email verification for password accounts and turns on password reset and "set a password" linking. Off by default; only takes effect when `RESEND_API_KEY` and `EMAIL_FROM` are both set.
|===

`EMAIL_SERVER` is no longer needed.

== Turning on verification

. Verify the `EMAIL_FROM` domain in Resend (add its DKIM/SPF records in DNS).
. Set `AUTH_EMAIL_VERIFICATION=true` in Netlify and redeploy.

Until then password accounts work without verification, and existing OAuth accounts cannot gain a password.
